# 息览 · Breath View

在 Linux 桌面离线读取 BMC U-20A 呼吸机 SD 卡，展示中文趋势和单夜波形。

## 用户与工作区

主要面向持续使用呼吸机的人进行日常记录查阅，也支持复诊时对照设备记录。界面按四项任务组织：

- **我的睡眠**：先看呼吸事件变化、平均戴机时间与基于自述的复诊建议；切换前期/去年同期，点击问号了解术语。完整分析和波形资料默认折叠。
- **每日详情**：定位治疗日与连续记录段，将流量、压力、漏气、事件及统计值放在同一工作区；必要时展开通气指标。
- **期间统计**：指定复查期间，核对使用时长、事件记录频率与数据覆盖，区分未结算、无摘要和无波形。
- **数据管理**：检查设备、数据来源、导入时间、读取异常和指标定义。

不使用宣传文案或综合打分。软件关注线用于方向性提醒，不作为诊断阈值。设备记录、程序计算与未知字段明确区分。

独立 GUI 安装在当前用户的本地工作区：

也可以在终端运行：


## 使用

- 顶部工具栏选择 SD 卡根目录，确认界面中的导入路径并点击导入。
- 默认打开“我的睡眠”，选取截至最新已结算记录的最近 30 天，可切换 7 / 30 / 90 天或自选日期。
- “比前期”比较相邻等长期间；“去年同期”按同月日对齐（闰日取 2 月 28 日），同时展示准确日期。数据不足或期间重叠不自动描述差值。
- “补充我的感受”记录不解乏、困倦、憋醒及佩戴问题。切换期间会暂存未保存草稿，关闭程序前请保存；导出只使用已保存自述。同一设备有以前保存的感受时，可以“载入上次感受”，逐项确认后保存到本期；备注默认不带入，旧回答不会静默更新本期判断。
- 首页突出本期间的记录截止日（设备日期），与导入时间分开；均值旁列出达到事件关注线和短用机的天数，点日期可复核。
- “治疗时间线”可新增、编辑、删除面罩更换、医生调整、舒适设置、作息或体重、生病等日期记录。只展示所选期间内的记录，对照调整前 7 天和从当天起 7 天；前后各有 7 个已结算日且事件频率可计算才比较。它描述同期变化，不判定因果，也不推算压力处方。当前感受按期间填写，时间线不会假装拥有调整前后的逐日症状。
- 点击“带去看医生 · 导出”，下载手机窄版 PDF 或离线 HTML。把文件发送到自己的手机即可离线查看，无需运行电脑服务。完整医生参考另在展开区下载。
- 每日详情中使用日期选择、前后日按钮或“最近有波形日”定位记录。
- 期间统计支持 7 / 30 / 90 天、全部及自定义起止日期；缺失摘要与未结算日分别显示。
- 单夜工作区同屏显示流量、压力、漏气、统计值与事件表。可选通气指标；支持同步光标、连续记录段选择、事件类型筛选。
- 拖拽曲线缩放，30 秒窗口查看原始流量；点击事件定位附近 5 分钟；滑条或箭头平移；双击或“全部记录”复原。
- CSV 按当前视图导出：每日详情导出当天，期间统计导出选定期间，数据管理导出全部。未结算日数值留空。无摘要日期不产生 CSV 记录。
- 数据与说明页展示解析边界、来源、导入时间、读取失败区间。

数据放在 `~/.local/share/breath-view/`，不写入 SD 卡。每次成功导入保留一个独立快照，`current` 指向本次快照；旧快照保留在磁盘，不自动删除。界面当前显示最新导入快照。拔卡后仍可查看。

所有页面与图表本地提供，不使用 CDN 或外部服务。仅监听 `127.0.0.1` 的随机端口，并使用随机能力 URL。无账户、遥测或云同步。提供有依据的初步判断与复诊准备建议，不生成确诊结论或调压处方。

## 精度与支持范围

目前只接受已经用实际数据验证的 U-20A。详细格式证据和尚未确认的字段见 [FORMAT.md](FORMAT.md)。事件指数由条目数量计算，不承诺等同原厂 AHI；不推断睡眠分期，不展示未确认的设置、血氧和鼾声，不给调压建议。

SD 卡发生 I/O 错误时，摘要读取失败会终止导入；波形不可读的 1 MiB 区间记录在清单并用无效包占位，解析时丢弃并断开曲线。副本的 SHA-256 是本地副本的校验值，有缺口时不代表完整原文件。导入失败不覆盖此前可用的数据。

图表概览采用极值保留抽样；不超过约 88 秒的流量区间可显示全部 25 Hz 原始点。跨开关机、不可读数据和缺失区间不插值。时间轴保留呼吸机时钟，不依赖电脑时区。

## 分析与结论

分析由 `analysis_report.py` 的可复核规则生成，不调用云端模型；患者首页由 `patient_summary.py` 综合事件水平、变化幅度、使用时长和症状，给出方向性判断。

- 用机时长来自历史摘要；事件频率按总事件条目数 / 总使用小时数加权，不平均每日频率。零时长日的事件不进入频率分子。
- 前后自动比较要求各至少 7 个已结算日、摘要覆盖率各 ≥70%。这是软件的数据充分性规则，不是临床阈值。
- 少于 4 小时只用于时长分档，不代表 4 小时已足够治疗。实际目标需核对全部睡眠时段的佩戴。
- 优先复核日期按事件条目频率、短用机、CSA 条目频率排序。最多审阅其中 3 个有波形日期，不外推到整个期间；无记录间隔只用作导航。
- 不解乏、困倦、戴机后憋醒、困倦驾驶、面罩问题、摘机和自报睡眠时长按设备序列号与分析起止日期存储于 `patient-contexts.json`（权限 0600）。未填写始终视作未知，不代填为无症状。
- 手机复诊摘要附上患者自述、前期及去年同期变化、重点日期、数据覆盖、建议与 AASM/ATS/NIH 来源。PDF 由已有 Qt 在独立离屏进程生成，各节为手机宽度页面并按内容自动延长；导出期间桌面事件循环不参与排版。HTML 无脚本、无远程资源，详细资料可展开。
- 首页直接给出“偏稳定 / 可能改善 / 有变差迹象 / 关注佩戴 / 建议复诊”等初步判断，并列出理由和把握程度。症状未填时仍给设备方向，未知不作“无症状”。
- 初筛关注线为估算事件频率 ≥5/h，或至少 3 天且占已结算日 ≥20% 达到该水平；只提示核对残余事件，不作 AHI 严重程度分级。该近似指标未与原厂校准，低于关注线不证明治疗充分。
- 前后变化同时达到 0.5/h 和 20% 才称明显变化，否则只说小幅变化。佩戴明显减少、短用机或睡眠自述与使用时长相差较大时优先提示覆盖问题，避免“事件下降”掩盖戴机不足。
- 以上变化幅度和天数是透明的软件判断规则，不是经临床验证的诊断标准。初步判断把握最高标为中等，详细规则在界面和报告中可查看。
- 当前设备解析未与原厂逐项核对，不能把事件频率当作已验证临床 AHI，也不能据此推断压力调整的因果效果、睡眠分期或氧合情况。

本次新增的必要验证包括加权分母、缺失/未结算排除、自述未知值与症状分支、期间隔离存储和报告转义。更广泛的使用验收及与原厂/临床证据的核对由使用者完成。

## 故障追踪

本机日志在 `~/.local/share/breath-view/breath-view.log`，记录界面响应、请求耗时和导出状态，不记录自述选项值或备注正文。保留至多 3 份、每份约 2 MiB。出现问题时记下大致时间，后续可直接对照日志。

## NAS 与数据更新

NAS 使用 Docker，监听容器端口 8080，持久化目录 `/data`。启动命令见 Dockerfile；使用非 root 用户 1000:1000，数据目录须属于此用户。访问路径包含保存在 `/data/access-token` 的随机令牌，重启后不变。请收藏完整地址，仅向自己的局域网或私有网络发布端口，不要公开分享健康记录链接。

网页导入：将同一张 SD 卡的 `.USR` 与同名 `.000`、`.001` 等编号文件压缩为 ZIP（可含外层文件夹），点击“导入”选择上传。最大压缩包及展开大小均为 8 GiB。更新上传完整新备份；成功后切换新快照，失败保留当前数据，旧快照与自述独立保留。仅上传 USR 会没有波形。浏览器不能通过服务器路径访问用户电脑，因此 NAS 不接受本地路径导入。

桌面版：顶部可选择数据文件夹，或“打开 .USR / ZIP”。选择 `20C03296.USR` 会读取同目录 `20C03296.000` 等编号文件；不要单独打开编号文件。也可执行 `./launch.sh /path/to/20C03296.USR` 或 `./launch.sh /path/to/card.zip`。打开即导入副本，原始数据不会修改。

治疗记录独立保存在服务数据目录的 `patient-changes.json`，权限 0600，按设备隔离，重新导入不覆盖它。感受仍使用兼容旧数据的 `patient-contexts.json`，新保存记录带保存时间。网页、完整报告和手机导出包含相同的已保存治疗变化及比较日期。
